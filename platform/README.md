# SipLink management platform (source)

The server that provisions SipLink Android clients centrally and serves LDAP directories: one Go program with a web console, keeping its data in SQLite.

- Deployment and use: [docs/platform.md](../docs/platform.md)
- Design: [docs/DESIGN.md](docs/DESIGN.md)
- Format of the configuration document sent to the phones: [docs/remote-configuration.md](../docs/remote-configuration.md); an example is [docs/examples/provisioning-document.json](docs/examples/provisioning-document.json) (generated by the tests from fixed input; its passwords and certificates are test data)

## Test data

`siplink seed {spec file}` creates or updates what the spec names: a region, a configuration template (one account, a CA, a hosted directory, an external directory), a key template, a client template and clients, and prints the address each client enrolls with. An example is [docs/examples/seed.example.json](docs/examples/seed.example.json); a password can be read from an environment variable with `passwordEnv` instead of being written into the file. Objects are found by name: running it again updates them and gives the clients new QR codes.

## Development

Go does not have to be installed on the host; every command runs in the official image (from this directory):

```sh
docker run --rm -v "$PWD":/src -w /src -v siplink-gomod:/go/pkg/mod golang:1.27.3-trixie go test ./...
docker run --rm -v "$PWD":/src -w /src -v siplink-gomod:/go/pkg/mod golang:1.27.3-trixie go vet ./...
docker build -t ghcr.io/tom231efa/siplink:dev .
```

`go test ./internal/provision -update` regenerates the reference examples of the configuration document (`internal/provision/testdata/` and `docs/examples/`).

Commands: `siplink serve | admin | pki | seed | backup | health | migrate | version`; `siplink help` shows the usage.
